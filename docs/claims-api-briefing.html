Stellarus · Claims API · Architecture take-home

GET /claims/:claimId

A fifteen-minute endpoint, delivered on the seams a healthcare platform will need.

The brief asked for one route: 200 on a hit, 404 on a miss, typed and tested. It shipped that, and used the change to put persistence behind a port, move validation into the type system, centralise error logging, fix money, and mark where identity plugs in. Every claim on this page traces to a file and a passing test.

05Data store & repository

The service stopped owning data. Persistence is now a binding, one line in AppModule.

Upstream, ClaimsService held the seed array and returned it by reference. Swapping to a database meant rewriting the service and its tests. Now the service depends on a port; the in-memory store is one adapter among the ones the platform will need.

claims.service.ts · upstreamannotations mine
@Injectable()
export class ClaimsService {
  private readonly claims: Claim[] = [
    { claimId: 'CLM-1001', …, amount: 425.5 },
    // ↑ float money, no currency
    …
  ];

  findAll(): Claim[] {
    return this.claims;
    // ↑ caller can push, sort, edit shared state
  }
}
claims.repository.ts · deliveredthe port
/** Port: abstracts claim retrieval and persistence.
 *  Abstract class doubles as the DI token. */
export abstract class ClaimsRepository {
  abstract findAll(): Promise<readonly Claim[]>;

  /** Resolves `undefined` when no claim has this id;
   *  rejects only on infrastructure failure. */
  abstract findById(
    claimId: ClaimId,
  ): Promise<Claim | undefined>;
}
app.module.ts · deliveredcomposition root
providers: [
  ClaimsService,
  { provide: ClaimsRepository, useClass: MockDataStore },

mock-data-store.ts · deliveredthe adapter
const copy = (claim: Claim): Claim =>
  ({ ...claim, amount: { ...claim.amount } });

async findById(claimId: ClaimId) {
  const claim = this.claims.find(
    (c) => c.claimId === claimId);
  return claim && copy(claim);
}
  • Persistence becomes a deployment decisionPostgres, a payer-core read model or a cache implements the port and changes one binding. Controller, service and their tests stay untouched.
  • Async from day oneThe port returns Promise even though the mock is synchronous, so a network-backed adapter needs no caller changes. The HTTP response is unchanged.
  • Miss semantics are in the contractResolve undefined for "not found", reject only for infrastructure failure. The 404 / 500 split falls out of that rule with no special cases.
  • Type-safe DI without string tokensAn abstract class survives compilation, so it serves as the injection token. No @Inject('CLAIMS_REPO'), no token drift.
  • Immutability enforced twicereadonly Claim[] stops mutation at compile time. Deep copies stop it at runtime; a spec mutates a result and asserts the store is unchanged.
  • The data layer cannot receive raw inputfindById takes a branded ClaimId, so an unvalidated string does not compile against the port.
  • Tests cut at the seamService specs use jest.Mocked<ClaimsRepository>. The e2e suite resolves the port from the container and forces a rejection to prove the generic 500.
  • Aligned with the target architectureThe review's ADR candidates are hexagonal boundaries and the payer core as system of record. This port is where that read model attaches.
postgres-claims.repository.tsillustrative · not in the repo
@Injectable()
export class PostgresClaimsRepository implements ClaimsRepository {
  constructor(private readonly db: Pool) {}

  async findById(id: ClaimId): Promise<Claim | undefined> {
    const { rows } = await this.db.query(
      'SELECT claim_id, member_id, status, amount_minor, currency FROM claims WHERE claim_id = $1', [id]);
    return rows[0] && toClaim(rows[0]);   // BIGINT minor units map straight to Money
  }
  // findAll …
}

06Validation as a type

Invalid input never reaches the store, and the compiler helps enforce it.

A branded ClaimId can only be produced by the type guard. The pipe produces it at the HTTP boundary; the service checks again for callers that are not HTTP.

claim-id.tszero dependencies
export const CLAIM_ID_PATTERN = /^CLM-\d{1,10}$/;

export type ClaimId = string & {
  readonly __brand: 'ClaimId';
};

export function isClaimId(
  value: unknown,
): value is ClaimId {
  return typeof value === 'string'
    && CLAIM_ID_PATTERN.test(value);
}
parse-claim-id.pipe.tsHTTP boundary
@Injectable()
export class ParseClaimIdPipe
  implements PipeTransform<unknown, ClaimId> {
  transform(value: unknown): ClaimId {
    if (!isClaimId(value)) {
      // Deliberately does not echo the input:
      // it is untrusted and may be oversize.
      throw new BadRequestException(
        CLAIM_ID_FORMAT_MESSAGE);
    }
    return value;
  }
}

Twice, on purpose

The pipe is the HTTP contract. The service re-check covers type casts, plain-JS callers and future entry points such as queue consumers and jobs. A spec asserts the repository is not called for bad ids.

Strict, not forgiving

No trimming, no upper-casing. Normalising would make two URLs return one resource and hide client bugs. clm-1001 is a 400.

Bounded

\d{1,10} caps length in the pattern itself, so a 10 KB id is rejected without a lookup. 26 specs cover bounds, whitespace, non-ASCII digits, SQL and path-traversal strings, and non-string values.

400 vs 404A malformed id is the client's error (400). A well-formed unknown id is a miss (404). Once authorization lands, a claim the caller may not see also returns 404, so responses do not reveal which ids exist.

07Errors & logging

Handlers throw. One filter logs. Clients never see internals.

Logging in controllers and services produces duplicate lines in inconsistent shapes. A single global filter gives one log shape, one severity policy and one place to change either.

all-exceptions.filter.tsexcerpt
const entry = {
  message, error, statusCode,
  method: httpAdapter.getRequestMethod(request),
  path:   httpAdapter.getRequestUrl(request),
};

if (statusCode >= 500) {
  this.logger.error(entry, stack, AllExceptionsFilter.name);
} else {
  this.logger.warn(entry, AllExceptionsFilter.name);
}

// A streaming handler may already have replied.
if (!httpAdapter.isHeadersSent(response)) {
  httpAdapter.reply(response, body, statusCode);
}
DecisionWhy it matters
4xx → warn, 5xx → error + stackClient errors stay visible for abuse detection without paging anyone
Unknown errors reply with a generic 500Messages and stacks go to logs only
Registered via APP_FILTERApplies in e2e tests as in production, so log assertions are real
JSON lines when NODE_ENV=productionReady for a log shipper; pretty output locally
Adds the fatal levelNest emits it and Winston's npm levels lack it, so fatal lines would be silently dropped
Validated LOG_LEVELUnknown values fall back to info instead of failing
bootstrap().catchStartup failures are logged through Winston and exit with code 1
Known gapThe log line includes the request path and the 404 message, and both contain the claim id. Claim numbers may be identifiers under HIPAA. Before real data arrives: log the route pattern or a hashed id, move the raw id to an audit trail, and add a correlation id per request.

08Money

Amounts are integer cents with a currency, before anything sums them.

Binary floats cannot represent most decimal fractions, so totals drift. In a claims domain that drift reaches adjudication and member statements. Fixing it now costs three seed rows; fixing it after persistence costs a migration.

ClaimBeforeAfter

CLM-1002810.25{ amountMinor: 81025, currency: 'USD' }
CLM-1003119.99{ amountMinor: 11999, currency: 'USD' }
claim.tsdomain type
export interface Money {
  /** Integer minor units (cents); never fractional. */
  amountMinor: number;
  /** ISO 4217 currency code. */
  currency: 'USD';
}

export interface Claim {
  claimId: string;
  memberId: string;
  status: 'PAID' | 'PENDING' | 'DENIED';
  amount: Money;
}
Trade-off statedThis is a breaking wire change for GET /claims: amount is now an object. No consumer exists yet, which is why now is the time. Formatting happens at the edge. Persist as BIGINT plus a currency column; move to bigint or a decimal type if values could pass Number.MAX_SAFE_INTEGER.

09Security seam

Identity plugs into a guard that already runs on every claims route.

There is no identity provider in the exercise, so nothing is authenticated. The change puts the seam where Nest expects it and marks each check with TODO(auth), so the eventual implementation is a fill-in, not a refactor.

Middleware→Guards→Interceptors→Pipes→Handler→Interceptors→Exception filters

Highlighted: slots this change uses. Guards run before pipes, so an unauthenticated request is rejected before validation or data access.

LayerQuestionWhereFailure
AuthenticationWho is calling?AuthGuard: verify the JWT against the IdP's JWKS, set request.user401
Role / scopeMay this kind of caller use this route?RolesGuard reading @Roles() via Reflector403
Object levelMay this caller see this claim?Controller or service, after the claim loads; a guard cannot see it404, same as missing
  • Guards, not interceptorsInterceptors run after guards and fit audit logging of PHI reads. Access decisions belong earlier.
  • Pinned by testsA controller spec reads GUARDS_METADATA and fails if @UseGuards(AuthGuard) is removed.
  • BOLA / IDOR named at the call siteThe object-level check is the top OWASP API risk, and its TODO sits exactly where the claim is loaded.
Fails openThe placeholder guard returns true. That is acceptable only because the exercise serves fictitious data. It must be replaced before anything real is served, and moved to a global APP_GUARD with a @Public() opt-out once there is a second controller.

11What comes next

Deliberately not built, and the order to build it in.

An architecture exercise is judged as much on what was left out as on what went in. Each deferral below has a reason and a phase.

  1. Phase 0 · hygieneMostly doneRemaining: .dockerignore, npm ci in Docker, engines, link docs from the root README.
  2. Phase 1 · contractAPI you can integrate againstResponse DTOs, OpenAPI, /v1, RFC 9457 problem+json, /health. ValidationPipe arrives with the first request body.
  3. Phase 2 · persistencePort done, adapter nextPostgres adapter behind ClaimsRepository, migrations, BIGINT money, Testcontainers integration tests.
  4. Phase 3 · securitySafe for PHIOIDC at gateway and guard, RolesGuard, object-level policy, audit interceptor, PHI-safe logs.
  5. Phase 4 · deliveryRepeatable and observableCI (build, lint, test, audit), image scan and SBOM, OpenTelemetry, SLOs, graceful shutdown.
  6. Phase 5 · integrationPlatform fitEvent-fed read model from the payer core, which remains the system of record. Attaches at the same port.

Working method with an AI assistant
